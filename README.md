# 🐦 Flappy Bird (Unity)

Классическая механика Flappy Bird, реализованная на Unity с акцентом на **чистую архитектуру и паттерны проектирования**. Проект демонстрирует, как даже в простой игре можно избежать «спагетти-кода», используя Object Pooling для производительности и Observer для слабой связанности систем.

## 🚀 О проекте

Это не просто клон популярной игры, а **референсная реализация** игрового цикла с разделением ответственности. Основная цель — показать, как паттерны проектирования решают конкретные проблемы: частые создание/уничтожение объектов (трубы) и необходимость обновлять UI и звук при столкновении, не превращая код в клубок взаимных вызовов.

**Ключевые возможности:**
*   Бесконечный игровой цикл с генерацией препятствий.
*   Плавное управление птицей (физика + анимация).
*   Система подсчёта очков и сохранение рекорда.
*   Звуковое сопровождение и визуальная обратная связь.
*   **Пул объектов** для труб (снижение нагрузки на GC).
*   **Событийная модель** для связи игровой логики с UI и звуком.

## 📂 Структура проекта

Проект организован по **функциональным зонам**, чтобы каждая система имела чёткую зону ответственности.

*   `Assets/Scripts/Game.cs` — **Центральный контроллер**. Управляет состояниями игры (Menu, Playing, GameOver) и координирует работу других систем.
*   `Assets/Scripts/ObjectPool.cs` — **Реализация пула объектов**. Хранит и переиспользует префабы труб вместо их постоянного создания и уничтожения.
*   `Assets/Scripts/PipeGenerator.cs` — **Генератор препятствий**. Отвечает за спавн труб из пула с заданным интервалом и случайной высотой.
*   `Assets/Scripts/Bird/` — Логика птицы: управление, физика, обработка столкновений.
*   `Assets/Scripts/UI/` — Экраны и элементы интерфейса (счёт, Game Over).
*   `Assets/Scripts/Save/` — Сервис сохранения рекорда (сериализация в JSON).
*   `Assets/Scripts/Sound/` — Менеджер аудио (эффекты полёта, столкновения, начисления очков).

## 🏗 Ключевые архитектурные решения

### 1. Object Pooling (Пул объектов)
**Проблема:** В Flappy Bird трубы постоянно создаются и уничтожаются. При высокой частоте это вызывает нагрузку на сборщик мусора (GC) и приводит к микро-фризам.
**Решение:** Вместо `Instantiate`/`Destroy` используется пул (`ObjectPool.cs`). Трубы изначально создаются в ограниченном количестве, а затем **активируются и деактивируются** по мере необходимости. Это критически важно для мобильной производительности.

// Пример: получение трубы из пула

pipe.transform.position = spawnPoint;
pipe.SetActive(true);
